# 声音设计

成片的质感有一半在声音上。这份文档管**怎么选音、怎么钉帧、怎么避免听觉翻车**。

> **落地形态说明**：我们的音频链路是「配音（TTS 或录音）+ 可选 BGM/SFX 混音」，
> 最终由 FFmpeg 合成。所以本文件的用法是**给出选音纪律与钉帧方式**，
> 具体落点是 `scripts/soundCue.mjs`（把 cue 表解析成音频轨上的绝对时间）
> 与 FFmpeg 的混音操作。

## 1. 顺序：画面先锁定，声音后进场

**画面结构基本锁定 → 先铺 BGM 定能量骨架 → 逐拍钉 SFX。**

这条顺序是硬经验：参考实现在画面改了约 30 轮之后才开始做音频，
有一次把「换 BGM」和「画面重做」混在同一轮改动里，画面随后继续改，
**SFX 全表报废重钉**。声音永远排在画面锁定之后。

## 2. 按「片种」选音，不按「事件」选

这是最容易翻车的一条。参考实现第一版按 UI 事件语义选音
（点击 / 落下 / 确认），用户一耳朵判死刑：**「太像游戏了」**。

- 产品宣传片的词汇 = **whoosh（运镜）/ impact（落地）/ riser（铺垫）/
  sparkle（光效）/ transition（转场）**。
- **禁用游戏音包的音色**：合成器拨弦、卡通弹跳、提示音式的「叮」。
- **禁的是音色，不是动作**：画面真有点击 / 开关 / 碎裂，就该配它的拟音；
  该用真实物件质感，而不是合成反馈提示音。

**判别问句**：这声音像**真实世界里那个物件发出的声音**，
还是像**游戏引擎的反馈提示音**？答不上来后者就换掉。

## 3. 音效目录（按场景/材质分类）

```
assets/audio/
  bgm/           BGM 备选
  sfx/<类别>/    按场景与材质分类
```

| 类别 | 装什么 | 什么时候用 |
| --- | --- | --- |
| `transition/` | whoosh / sweep / 风 | 运镜、场景切换、元素飞入飞走 |
| `impact/` | impact / thud / stomp / bass hit | 落地钉点、重拍、砸入 |
| `riser/` | 上升铺垫 | 进入高潮前的能量铺垫 |
| `camera/` | 快门、镜头、变焦 | 拍照感、急推、对焦 |
| `ui/` | 点击、开关、通知 | UI 反馈、列表落入（**这个目录要逐个试听**——里面既有真实拟音也有合成反馈音） |
| `text/` | 打字机、键盘、书写 | 文字揭示、描线 |
| `paper/` | 纸、翻页 | 纸张材质动作 |
| `light/` | 光效 | 泛光、闪烁（词汇表里的 sparkle 在这里，没有 `sparkle/` 目录） |

**找音先定类别，再挑音色** —— 按要配的画面动作查上表，进对应目录试听。

## 4. 钉帧：一律相对镜头起点

**绝不写裸帧号或裸秒数。**

```
{ "shot": "s03", "offset": 0.4, "src": "whoosh-soft.mp3", "volume": 0.55, "what": "卡片上浮" }
```

`offset` 是相对镜头起点的秒数。这样时间线整体平移时全表自动跟随；
写成绝对时间则每次改期都要逐个对帧。

由 `scripts/soundCue.mjs` 解析成绝对时间，并核两条：

- **镜尾保护带**（默认 0.5s）：锚点距镜头出点太近时落点会被转场吞掉，
  听起来像「没响」或「响晚了」。
- **片头边界**：补偿后时刻不能为负，所以重音不要设计在片头最前面。

## 5. 音量是乘法系数，不是目标音量

`volume` 是**乘法系数**：

- 素材本身录得轻（峰值低）时，给 1.0 也压不住 BGM —— 正确做法是
  **换素材 / 预归一化 / 给足增益**，而不是靠一个 >1 的数硬顶。
- 写了 >1 的值时脚本会警告，提示优先换素材。
- **BGM 音量要压在给 SFX 留 headroom 的位置**（参考实现用 0.34 左右）。

## 6. 防「机枪感」三招

连续同类音效密集出现会读作机关枪。参考实现的处置：

1. **双样本交替** —— 不要同一个文件连打。
2. **音量阶梯递减**（例如 0.40 → 0.25）。
3. **间隔跟随动画加速** —— 动画越来越快时，间隔也跟着变。

密到糊就**淡出成一条 whoosh**，而不是继续叠。

## 7. 长样本与结尾句式

- **长样本（>5s）必须显式给时长**，否则会拖到动作结束后还在响。
- 结尾能量：`riser → impact → sparkle` 三段句式成立时最有收束感。
- **强节奏音乐的切点误差 ≤3 帧**（感知阈值约 3 帧）；
  卡点密集的片子要按 `references/beatSync.md` 的流程核。

## 8. 输出音轨偏移（必须实测，不能照抄）

AAC 编码器的 priming 会让**整条音轨滞后**：

| 编码器 | priming |
| --- | --- |
| ffmpeg 内置 aac | 1024 samples（48kHz 下 ≈21.3ms ≈ 0.64 帧 @30fps） |
| fdk-aac | 2048 samples |
| Apple | 约 2112 samples |

参考实现实测（Remotion 4.x + AAC 48kHz mp4，双探针交叉相关）滞后 ≈1.28 帧。

**统一公式**：

```
音效起始时刻 = 目标峰值时刻 − 音源自身峰值滞后 − 输出音轨偏移
```

**这个常数必须按自己的渲染管线实测**，不能照抄别家的数：

1. 渲染一小段带尖锐音效的片段；
2. 抽出音轨，与源素材做**归一化交叉相关**；
3. 读出的偏移量即为常数，传给 `soundCue.mjs --offset-ms`；
4. 补偿后重渲，对 2~3 个探针复测，**残差 ≤0.5 帧为合格**。

`--offset-ms` 默认 0 且会在输出里明确提示「未做补偿」——
不塞一个看起来合理但其实错的值。

## 9. BGM

- **一条 BGM 全片铺底**，音量用包络做首尾淡入淡出
  （参考实现是 1s 淡入、1.7s 淡出）。
- **曲子的能量曲线要和分镜的能量曲线对得上**（低开 → 中段推进 → 结尾峰值）。
- **候选曲必须垫进成片试听** —— 单听曲子无法判断气质。
  参考实现为此被否了两稿，第二稿与第一稿只隔 22 分钟。
- 判据是「**鼓点强、节奏感强**」，不是「好听 / 欢快」。
  气质基准：闭眼只听音轨，应像产品发布会预告，不像手机游戏。
- **配了 BGM 的片子交付两版**：带 BGM 版 + 无 BGM 版（同一时间线渲出，
  无 BGM 版画面与 SFX 与带 BGM 版逐帧一致），方便用户后期自配音乐。

## 10. 混音收尾

- 用**两遍 loudnorm**（单遍是动态模式，会压音效瞬态）：
  第一遍只量测并读出 JSON，第二遍用 `linear=true` 加实测值做线性归一。
- loudnorm 内部会升到 192kHz，**不加 `-ar` 会把高采样率漏进 AAC** —— 显式写 `-ar 48000`。
- 归一之后音效相对电平会变，**交付前必须重新核一遍音效可听度**
  （人声是否掩蔽了音效、音效是否压了人声）。
