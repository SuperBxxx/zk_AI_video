# BGM 卡点（强节奏音乐的转场与动效对齐）

强节奏 BGM 的片子，**所有转场和关键动效必须落在拍上**。
本文给出从「拿到一首曲子」到「切点误差 ≤3 帧」的可复现流程。

> **落地形态说明**：参考实现用 Python 的 librosa 做节拍分析，我们零 Python。
> 所以本文**先给出方法论与验收口径**（这些与工具无关），
> 具体分析工具的选择见 §6 —— 没有合适的 TS 方案时，
> 正确做法是**降级为「只做淡入淡出、不做卡点」**，而不是凭听感钉点。

## 0. 何时启用

- 用户**已指定音乐** → 走本文：先分析节奏，再让分镜的每个切点与动效锚到拍号。
- 用户**未指定** → BGM 选型放到后期，此时动效时间线按**内容节奏**排，不强行卡点。

**铁律：音乐先行。** 网格没验收通过之前不设计分镜；
时长对不上时改时间参数，**不删改用户文案**。
全程用浮点秒记录时刻，**换算成帧只在最后一步**（提前取整会让误差在管线里滚雪球）。

## 1. 节拍网格测定：不要相信 tempo 标量

节拍检测工具返回的 **tempo 标量可能偏差 2% 以上**
（参考实现实测报 129.2，真值 131.97）。但它输出的 **beat 时刻序列本身是好的**。

正确做法：**对 beat 序列做最小二乘等距网格拟合**，求真实周期与相位。

```
把 beat 时刻记为 beats[i]，拟合 t_i = t0 + i × T
  用最小二乘解出 (T, t0)
  bpm = 60 / T
  残差 = beats[i] − (t0 + i × T)
```

**验收标准：残差 ≤ ±15ms（半帧内）** 说明曲子是机器鼓点、网格可信；
残差大说明有变速段，需要分段拟合。

**半倍/双倍歧义必查**：beat 检测常在 2x / 0.5x 之间跳（70 BPM 报成 140）。
判据不是听感 —— 正确的网格下 kick 应该主要落在整数拍；
如果 kick 一半落拍、一半落半拍，多半是网格快了一倍。
拿 0.5x / 1x / 2x 三个候选各算一遍分数，选覆盖率最高的。

**复杂曲先分离鼓 stem**：人声 / 贝斯厚的编曲会把鼓的攻击埋掉，
检测会漂。轻量做法是取打击成分（高通 + 瞬态），重做法是先分离整条鼓轨，
**之后所有鼓点检测都在鼓轨上做，不在全混音上做**。

## 2. 鼓点分类与能量结构

### 2a. 三分类瞬态检测

不同鼓件驱动不同类型的动效，**分频段各测一遍**：

| 类别 | 频段 | 驱动的动效 |
| --- | --- | --- |
| kick | 40–160 Hz | 冲击 / 砸入 / 骤缩 —— 画面「被砸」的一拍 |
| snare | 150–500 Hz 体 + 1–3 kHz 打击面（两者都要有） | 替换 / 闪切 / 构图切换 —— 「换一件事」的一拍 |
| hihat | 6–14 kHz | 微动密度 —— hihat 密的段落微动效可以密，稀的段落必须收 |

把每个整数拍位置的各频段能量列出来，记录成 `{时刻, 强度, 类别}` 的清单存档。

**命中表是候选池，不是触发器。** 检测到的每个 kick 不等于都要配一次画面冲击：

> 参考实现的实际用户投诉：「如果给音乐，镜头会随节奏抖动，影响观感」。
> 根因是把 kick→冲击 执行成了逐拍全画面泵 —— 强鼓点曲 kick 几乎每拍都有，
> 逐拍「被砸」叠上相机层就是节拍频率的画面抖动。

**约束**：

- 作用于**整画面或相机层**的冲击（整画面缩放泵 / 震屏 / 闪帧）全片 **≤3 处**，
  且相邻两处间隔 **≥16 拍**；
- 其余拍点只作用在**主角元素层**；
- 节拍泵类连打**单次 ≤4 拍、全片 ≤1 次**；
- 计数单位是**一次手法**，不按内部子事件数 ——
  一张卡的一次应用（三连闪、黑帧串、三刀切）算一个名额。

### 2b. 能量曲线与结构表

拉全曲能量曲线，配合鼓点密度切出段落边界。产出两样东西：

- **音乐结构表**：能量从第几拍起满、breakdown / 静默段在第几拍 ——
  分镜的能量曲线要贴着它排（breakdown 处放品牌呼吸位是天然结构）；
- **最强 hit 拍号清单**：全片 2–3 个最大冲击（开题 / 高潮 / 收尾）必须钉在这些拍上。

**易错点**：参考实现把最大冲击钉在了两拍之间（b52.5）而最强 kick 在整数拍 b52 上，
渲后回测偏差 +5.75 帧。**强鼓点曲的重音几乎总在整数拍上，
半拍钉点必须有能量数据支持，不能凭听感。**

## 3. 网格验收（先验收，后分镜）

拿候选网格（含 0.5x / 1x / 2x）逐一对齐最近的真实鼓点瞬态，算四个指标：

| 指标 | 含义 | 门槛 |
| --- | --- | --- |
| match | 网格拍命中真实瞬态的比例 | ≥98% |
| mean_abs_ms | 平均绝对对齐误差 | <10ms |
| drift | 残差对时间做线性回归的斜率 | 全曲累计 <5ms |
| 首拍有效性 | 网格第 0 拍是否落在真实的音乐攻击上 | 必须 |

按分数选出获胜网格，把**所有候选和获胜理由**留档。
拿不准时可以给候选网格各合成一条点击轨叠回原曲听，
但**最终以指标定夺，不以听感定夺**。

## 4. 用拍号编排时间线

分析产物是每一个切点的审计链，随项目留档：

```
analysis/
  beat_data.json    # bpm, t0, T, beats[], hits[], energy[], sections[]
  grid_drift.json   # 各候选网格的四个指标
```

代码侧只暴露两个派生量：

```
源音乐分析 t0（真值，永不掺入渲染偏移）
输出音轨偏移（按渲染管线实测，见 references/soundDesign.md §8）
拍号 → 秒：t0 + 输出偏移 + n × 周期
```

**全片切点随这一个函数一次归位，不要逐锚点手改拍号。**

## 5. 渲后回测

渲出后把成片的实际切点与拍号对齐，核**全片切点误差 ≤3 帧**。
若有**系统性同向偏移**，先查输出音轨偏移（§4 的第二个常量），
**不要逐点手改** —— 系统性偏移说明是管线常数的账，不是每一拍都算错了。

## 6. 工具选择（我们的约束）

参考实现用 Python 的 librosa（`uv run --with librosa`），我们**零 Python**，
需要 TS 侧的等价方案。三条路：

| 路线 | 代价 | 说明 |
| --- | --- | --- |
| TS 音频分析库（如 essentia.js 一类） | 需要引入依赖 | 能做节拍与频段能量，但需自行验证上面四个指标 |
| 用 FFmpeg 做预处理 + 自写检测 | 无新依赖 | FFmpeg 可抽音频、分频段、算能量包络；节拍网格与瞬态分类要自己写 |
| **降级：不做卡点** | 0 | 只做 BGM 淡入淡出与内容节奏对齐 |

**降级的正确姿势**：明确告诉用户「本片未做音乐卡点」，
而不是凭听感钉几个点然后声称已卡点 —— 那比不卡点更糟，
因为观众会感到「说不出的不对劲」而说不出哪里不对。
