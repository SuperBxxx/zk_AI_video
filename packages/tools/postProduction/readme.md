# 后期制作

成片交付前的质检与字幕工具。

## checkVideo — 成片质量闸

判据来自已交付项目的返工教训，**交付前必跑**：

| 闸 | 判据 | 依据 |
| --- | --- | --- |
| 帧率 | `r_frame_rate` 必须等于 `avg_frame_rate` 且等于目标帧率 | 不等 = 变帧率或丢帧，混剪时每 N 帧出现一次重复帧 |
| 音画时长 | 差 ≤ 1 帧 | 超过即算失败 |
| 静止段 | 任意 0.8s 不允许全静止 | 素材本身要求静止的段落，处置是让画面持续微动，不是豁免 |
| 镜头落点 | 每个镜头 ≥ 保护带（默认 0.5s） | 太短会让动效落点被转场吞掉 |

## makeSubtitle — 配音对齐出字幕

把**配音的实际念法**对齐到**我们的稿子**，产出可直接烧录的 ASS。

- **稿子是句子的权威**，不是语音识别的停顿 —— 语音识别会按自己的气口把前两句并成一段。
- 语音识别会把「三千」写成「3000」、「十九万」写成「19万」，工具内部归一化，稿子两种写法都行。
- 返回每句的 `match` 覆盖率，**`match < 0.90` 要人工听核**（通常是识别听错了）。
- 逐字高亮用 ASS 卡拉 OK 标签。

烧录交给 ffmpeg 工具（ASS 与视频同目录，滤镜只传文件名）：

```json
{"steps":[{"method":"input","args":["视频.mp4"]},{"method":"videoFilters","args":["subtitles=字幕.ass"]}],
 "operation":{"method":"save","args":["输出.mp4"]}}
```

## resolveCues — 音效钉帧

校验 cue 表并换算成音频轨上的绝对时刻。

- 钉帧**一律相对镜头起点**；写绝对时间会在时间线平移时全表失效。
- 音量是**乘法系数**不是目标音量；素材录得轻时优先换素材或预归一化。
- 输出音轨有编码器 priming 偏移（内置 aac 约 21ms），
  **这个常数必须按自己的管线实测后传入**，不要照抄别家的值。

## exportDelivery — 导出可编辑交付物

把镜头表与字幕导出成**平台无关**的可编辑数据：

| 产出 | 用途 |
| --- | --- |
| `*-edit.csv` | 镜头切段表（序号/源/源入点/时长/时间线落点），任何剪辑软件或表格工具可读 |
| `*-edit.edl` | 标准 CMX3600 EDL；**仅单源素材时导出**，多源会拒绝并让你改用 CSV |
| `*.srt` | SRT 字幕（不带样式，便于在别的软件里继续改） |

导出前会对切段表**对账**：同轨重叠、缝隙、零长段、总时长不符、负源入点。
对账不过就**不写任何文件** —— 给出坏数据比不给更糟，用户会在剪辑软件里才发现。

**为什么不做剪映/Premiere 的内部工程格式**：那是私有的、随版本变。
没有真机草稿做基准时照猜生成，只会给出打不开的坏文件。
本工具只产出有公开格式、能自己校验的东西。

时间量一律用**微秒**，且相邻段边界遵守「起点与终点各自取整后再相减」——
起点与时长分别取整会产生 1µs 级缝隙或重叠，而剪辑软件对同轨重叠是直接报错的。

传 `jianying` 参数时额外产出剪映草稿（与 CSV/SRT 并列，不是替代）：

```
assets/delivery/<草稿名>/draft_content.json
assets/delivery/<草稿名>/draft_meta_info.json
```

- **底片（plate）必须是无字幕、无音效的干净成片** —— 字幕与音效在草稿里是可编辑的独立轨，
  重复烘焙会变成剪映里叠两层字幕。
- 底片按镜头切成多段（`source_timerange` = `target_timerange`），所以每段可在剪映里
  单独变速、重排、删减。
- 实测：底片素材时长由 ffprobe 真实读出后登记；底片轨各段首尾**严格相接**（微秒边界铁律）。

**格式来源**：字段结构逐项对照 [pyJianYingDraft](https://pypi.org/project/pyJianYingDraft/)
0.3.0 的序列化器（`local_materials.py` / `segment.py` / `video_segment.py` /
`audio_segment.py` / `text_segment.py` / `track.py` / `script_file.py`）与它的两个模板资源。
其中几个反直觉但必须照抄的点：

| 点 | 说明 |
|---|---|
| 入口文件名 | Windows 是 `draft_content.json`（Mac 是 `draft_info.json`） |
| 片段 `render_index` | 等于**轨道序号**，不是 0；`track_render_index` 一律 0 |
| `texts[].content` | 是**序列化后的字符串**，不是嵌套对象 |
| 素材登记 | 音视频素材必须同时进 `draft_meta_info.draft_materials[type 0]`，漏了剪映弹「媒体丢失」 |
| `materials` 的键 | 44 个键一个都不能少（缺键可能被判定为损坏） |
| 时间单位 | 全部微秒 |

> ⚠️ **未验证**：「剪映能打开这份草稿」在开发机上无法验证（没装剪映）。
> 字段结构、素材引用、轨道不重叠、时长一致性都由 `scripts/checkJianying.mjs`
> 做常驻对账（143 个字段 + 结构不变量，已接入 `preflight`），但**缺字段的实际后果
> 只有剪映知道**。首次使用请先做最小草稿冒烟。


## useCard — 画面配方卡

把「画面效果」变成可复用、可校验的词汇。两种用法：

1. **检索**：按素材类型（`inputs`）与语义（`semantics`）出候选，
   带排序理由；给不出候选时如实说「库里没有」。
2. **取卡**：给 `slug` 取完整内容 —— 参数化的 FFmpeg 滤镜链、已知坑、落位自检。
   可传 `parameters`，越界或未知参数会被拒（不会悄悄产出一个坏滤镜）。

卡吃哪种素材（`inputs`）：`人`/`V`/`图`/`截图`/`文`/`界`/`场`（`场` 是作用于前后两镜的转场）。

首批 7 张卡都是**本机 ffmpeg 实跑验证过**的：`slowPushIn`（极缓推进）、
`fadeEdges`（首尾淡入淡出）、`crossFade`（交叉淡化）、`desaturateBed`（降饱和底床）、
`vignetteFocus`（暗角收拢视线）、`holdLastFrame`（冻结末帧留白）、
`flashCut`（硬切闪白 —— 从上游 video-shotcraft 的 `FlashCut.tsx` 移植的第一个效果）。

**关于上游的卡**：上游那 221 个是 **Remotion/React 组件**（`AbsoluteFill` + `useCurrentFrame`
+ `interpolate`），逐帧执行 JavaScript 渲染，FFmpeg 无法表达。其中**只有少数能用纯滤镜链
等价表达**（`flashCut` 就是其一）；其余需要按「生成模型出画面 + FFmpeg 组装」的形态重做，
不能直接抄。

**与参考实现的差异**：参考实现的卡是可直接渲染的组件（tsx）。
我们的画面由生成模型产出、由 FFmpeg 组装，所以这里的卡是
**参数化滤镜链 + 使用说明**，不做逐帧程序化渲染（那超出 FFmpeg 的表达能力）。

`scripts/checkCards.mjs` 会逐张真跑一遍并核**语义效果**（不只是「能跑」），
`bun run preflight` 已把它变成必需项。加卡时若滤镜链跑不通或效果不对，preflight 直接失败。
