## 二、研究结论（避免重复劳动的关键信息）

用 logo-design 技能的 1400+ 参考库查过分类惯例：

| 类别 | 库中现状 | 应避开 |
| --- | --- | --- |
| `ai-ml` | abstract 标记为主；**蓝色占 33%**；圆/六边形；单线描；放射对称 | 通用「AI 节点 / Sparkle / 原子」图形、蓝色 |
| `media-entertainment` | **红色占 27%**；播放按钮；胶片孔/齿轮 | 播放三角、胶片圈 |

**绿色在两类中都很罕见** —— 竹绿本身即差异化，这是优势，应保留。

**已被用尽的套路**（库中范例很密，不宜再走）：
- 「方形边框 + 负空间字母」：`pagekit.svg`（P）、`kotlin-icon.svg`（三角切出 K）、
  `npm-icon.svg`、`manjaro.svg`
- 「容器 + 播放三角」：`youtube-icon.svg`、`leankit-icon.svg`（六边形切三角）

## 三、已产出的概念与结论

### 第 1 轮三个概念（全部**否决**）

| 概念 | 实际读作 | 否决原因 |
| --- | --- | --- |
| A 带节画框 | 4 个直角**括号** | 缺口全在中段，四边相等，完全不像竹子 |
| B 分节生长 | **信号强度 / 下拉柱状图**，且在**下降** | 与「生长」语义相反；断开方块像骨架屏 |
| C 画格 | UI 缩略图 / 对齐辅助线 | 无身份，泛 UI 化 |

**教训**：必须渲染出来亲眼看。这几个概念在代码层面都"正确"，是视觉上不成立。

### 第 2 轮三个概念

| 概念 | 评价 |
| --- | --- |
| A2/A3 住字标 | 可辨认，但「主」的点与竖合并、字形为**近似**而非规范字，可能被挑字 |
| **B 框与三角** | **用户选定**。干净、16px 可辨、角度可复算 |
| C 叠帧 | 16px 下糊成一团，需单独小尺寸切版 |

### B 的定稿几何（`concepts/b8-frame-play-final.svg`）

```
外沿 32..224（边长 192），边宽 30，四边留白 32，标记占 75%
右下缺口：底边止于 x194、右边止于 y164，缺口 30 见方
内区 62..194
三角：底 x98，y88..166（高 78），顶点 (143,127)
顶角 θ = 2·atan(45/78) = 59.9°
由四段实心矩形 + 一个三角子路径构成（even-odd），不依赖 stroke
```

审计：**100/100 无问题**；像素实测四边留白均为 32。
`b5-frame-play.svg` 是紧凑化之前的版本（留白 40）可作对比。

## 四、下一轮改用 logo-generator 技能时要注意

该技能的产出方式与本目录不同，需要适配：

1. **它要求 `viewBox="0 0 100 100"`**，而本目录现有文件是 `0 0 256 256`。
   若沿用 B 的几何，需要等比换算。
2. **它一次产出 6+ 个变体**（本目录只做了 3 个），并要求生成 HTML 交互展示页。
3. **它可以调用 Gemini（Nano Banana）生成展示图**，需要 API key
   （`.env` 里的 `GEMINI_API_KEY`）。**若没有 key，展示图这一步做不了** ——
   要如实告知，不要假装生成过。
4. 它的设计原则里强调「extreme simplicity、generous negative space」，
   与 B 的方向一致。

### 建议

- 把上面第一节的 brief 原样喂给新技能，不必重新问一遍
- 要求它**保留竹绿 `#2E9E6B`**，并避开第二节列出的已用尽套路
- 让至少一个变体延续「框与三角」方向（用户已选），其余探索新方向供对比
- 产出后**务必渲染出来亲眼看**，尤其检查 16px —— C 概念就是栽在这里
